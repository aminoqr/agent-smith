# M3.5 notes for the teammate: hardening the sandbox

1. **Memory limit:** the worker asks the OS to cap its memory (`resource.setrlimit`, from `max_memory_mb`), so a memory bomb gives a clear `MemoryError` message instead of freezing the machine. It is set in the worker, never in the controller, because a limit applies to the process that sets it.
2. **Audit hook (`audit.py`):** Python announces sensitive actions (opening files, sockets, starting programs, killing processes) and the hook can refuse them, whatever route the code used. It only acts while the model's code runs (`enforcing()`), and it still lets Python read its own library files so imports work.
3. **Secrets:** the worker clears its whole environment at startup, because the agent's environment holds the API keys and model code could otherwise read them.
4. **Closing sneaky routes:** names like `__self__` and `__import__` are refused by the AST check, and `getattr`/`hasattr`/`setattr`/`delattr` are wrapped so a name built at run time (`'__se' + 'lf__'`) is refused too. Honest limit: an allowed module like `operator.attrgetter` can still reach those objects; what stops real damage then is the audit hook, the cleared environment, and the separate process.
5. **Control flow:** `SystemExit` and `KeyboardInterrupt` raised by the model's code, and a real Ctrl+C, reach the agent instead of being swallowed or killing the worker silently. Python's own hidden imports for `datetime` (`strptime`, `strftime`, `today`) are allowed without allowing the model's own `import time`. `uv run pytest -q` shows 106 passed.
