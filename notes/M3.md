# M3 notes for the teammate: the sandbox worker process

1. **Why a second process:** code that never ends would freeze the agent if it ran in the agent's own process. The code runs in a *worker* (`worker.py`), which the *controller* (`controller.py`, class `Sandbox`) can kill at any time. The worker keeps one namespace, so variables persist between steps.
2. **Talking to the worker:** the two processes exchange small JSON messages through a pipe (`protocol.py`). JSON, never pickle: pickle can run code when loaded, and the worker is untrusted.
3. **Two timeouts:** a *soft* one (`SIGALRM` raises `SandboxTimeout` inside the worker, variables are kept) and a *hard* one (the controller kills and restarts the worker after limit + 2 s, variables are lost). Code stuck in C, like `sum(range(10**12))`, can only be stopped by the hard one.
4. **Output** is streamed from the worker while the code runs, so a hard kill still leaves what was printed so far. It is capped at 10,000 characters, with a note saying so.
5. **A worker that dies** (crash, killed) is replaced, and the model gets a clear message instead of the agent crashing. `uv run pytest -q` shows 79 passed.
