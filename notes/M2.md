# M2 notes for the teammate: sandbox policy layer (in-process)

1. **Where it lives:** `agent_smith/sandbox/policy.py` (allowlist, import guard, safe builtins, path guard, AST check) and `agent_smith/sandbox/runtime.py` (`execute(code, namespace)`, the thing that actually runs model code and reports what happened).
2. **Imports are checked by replacing `__import__`** with a function that checks the requested module name against `SandboxConfig.authorized_imports` (glob patterns: `"math"` is exact, `"math.*"` covers submodules). Watch for the `fromlist` hole — `from collections import abc` hides the submodule name, so we also check `sys.modules` after the real import.
3. **Builtins are a *copy* of the real dict** with dangerous names (`eval`, `exec`, `compile`, `input`, `globals`, ...) swapped for stubs that raise `SandboxSecurityError`. Never mutate `vars(builtins)` directly — that's the live interpreter's own dict.
4. **Paths are checked with `os.path.realpath` + `os.path.commonpath`**, never `startswith` — that's the only way to catch `..` traversal and symlinks pointing outside the allowed directories.
5. **`execute()` is REPL-style:** persistent namespace across calls, last bare expression echoed (like typing in a REPL), stdout captured, errors turned into one line with the model's line number. It never catches `SystemExit`/`KeyboardInterrupt` — those must reach the agent loop.
6. **Known limit, by design:** the AST check (step 2.6) only blocks *literal* attribute/name tokens like `__subclasses__`. A name built at runtime slips through. This layer is "defense in depth, not a perfect wall" — M3/M3.5 add the real containment (process isolation, resource limits, an audit hook).
